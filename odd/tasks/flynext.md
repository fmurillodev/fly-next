## Specs

Full text of D01–D10 lives in `docs/engineering/DOMAIN-DECISIONS.md`; the strings below are quoted from the approved Master Engineering Specification v1.0.

- **S1 Identity.** Product "FlyNext"; repo "fly-next"; packages `@flynext/api`, `@flynext/web`, `@flynext/contracts`; tagline "Your journey. Your next step."; "FlyNext es una solución demostrativa independiente, no un producto oficial de LATAM."
- **S2 Challenge constraints.** "Presupuesto máximo efectivo: tres horas, incluyendo análisis, implementación, validación, documentación y preparación." Ten-minute presentation; public GitHub repo; API public over HTTPS; README ≤ 2 pages; AI Usage & Decision Note ≤ 1 page; reproducible evidence. "No reiniciar el presupuesto de tres horas."
- **S3 Stack.** Node.js 24 LTS, TypeScript strict, pnpm workspaces, Fastify, React 19, Vite, Tailwind CSS v4, Axios, Zod, Vitest, Pino, Swagger/OpenAPI, ESLint, Prettier, tsup (if compatible), GitHub Actions, Railway, @fastify/static. "No incorporar Turborepo, NestJS, PostgreSQL, Redis, Prisma, servicios de mensajería ni frameworks adicionales sin autorización." Pin exact versions in PR-01; consult current docs (Context7) first.
- **S4 Architecture.** Monorepo `apps/api`, `apps/web`, `packages/contracts`. Backend: pragmatic hexagonal, main module `disruption` with `domain`, `application`, `infrastructure`, `presentation`; cross-cutting: config, errors, HTTP client, observability. Manual DI, Ports & Adapters, DTO Mapper, Use Case; Strategy only on concrete need. "El dominio no depende de Fastify, Axios, React ni implementaciones de infraestructura." "No compartir entidades internas ni lógica de negocio con el frontend." No speculative abstractions or empty folders.
- **S5 Deployment.** Railway only; one Node.js service exposing `GET /` (built React when available), `GET /health`, `GET /docs`, `POST /api/v1/disruptions/assessment`. Fastify serves static via @fastify/static; SPA fallback must not intercept API, Swagger or health. Vite proxy in dev. Listen on `0.0.0.0` and `PORT`. Stateless. No Neon/other DB, no Vercel. "El despliegue inicial debe realizarse tempranamente".
- **S6 Base case ABC123.** Synthetic booking; Santiago–Lima–Ciudad de México; two passengers, one minor. S1 LA500 14:30→17:55, delay 160 min, new departure 17:10, gate 24. S2 LA2410 19:05→23:40, SCHEDULED. Original connection 70 min; projected arrival 20:35 (90 min after connection departure) "no constituye una llegada confirmada". OPS_CORE vs LEGACY_MIRROR contradiction (LEGACY_MIRROR degraded). Fare conditions incomplete; changes allowed, penalty unknown. Expected: delay 160 confirmed, gate 24, connection AT_RISK, loss not confirmed, PARTIAL, HUMAN_REVIEW, priority HIGH, no free-rebooking guarantee, no compensation guarantee, no write operations.
- **S7 D01 Classification.** Cancellation critical; delay ≥ 30 min relevant; delay < 30 informative; gate change informative; connection at risk critical; confirmed missed connection critical; airport change critical; unresolved contradiction indeterminate. "Un retraso inferior a 30 minutos también será relevante si compromete una conexión." 30-min threshold is a configurable product assumption. Implement only events needed by V1 scenarios.
- **S8 D02 Source authority.** OPS_CORE: status/times; AIRPORT_FEED: gates; LEGACY_MIRROR: secondary. Consider authority by information type, timestamp, freshness, source status. "Una fuente degradada no puede fundamentar una decisión definitiva." Same-source equivalent valid events: latest wins. No reliable resolution → explicit uncertainty. Record contradictions and reconciliation via sanitized references. Hierarchy is an unvalidated integration assumption.
- **S9 D03 Freshness.** Booking context 5 min since retrieval; operational events 30 min since record; gates 15 min since record; alternatives provider TTL (120 s in base case); policies verifiable validity and active version. First three are configurable assumptions. Injectable Clock; explicit reproducible simulation mode for historical fixtures; base-case reference date `2026-09-15T11:02:40Z`. [A02] ISO 8601 with explicit offset; IANA zones America/Santiago, America/Lima, America/Mexico_City; comparisons, durations and freshness in UTC; local times shown to the passenger; offsets verified per date, never assumed constant; S1 estimated arrival remains a projection. "No presentar datos históricos como información operacional en tiempo real."
- **S10 D04 Connections.** States SAFE, AT_RISK, MISSED, UNKNOWN. "No declarar MISSED a partir de una estimación." "No inventar Minimum Connection Time." SAFE only with sufficient evidence. ABC123 → AT_RISK. Distinguish absence of loss confirmation from confirmation that the connection was not lost.
- **S11 D05 Policies.** R1 delay ≥ 180 → REBOOK_NO_FEE; R2 delay ≥ 240 and international → MEAL_VOUCHER; R3 confirmed missed connection → REBOOK_NO_FEE; R4 compensation requested → CASH_COMPENSATION (human approval); R5 group includes minor → PRIORITY_HANDLING (human approval). Reference policy POL-DELAY-2026-03. Statuses APPLICABLE, NOT_APPLICABLE, REQUIRES_HUMAN_APPROVAL, INSUFFICIENT_EVIDENCE. No `eval`. Unknown/invalid/expired/unsupported policies grant nothing. ABC123: R1 no, R2 no, R3 insufficient evidence, R4 not requested, R5 requires human approval. [A03] R4 is NOT_APPLICABLE when no monetary compensation was requested; ABC123 → NOT_APPLICABLE.
- **S12 D06 Alternatives.** Validate seats for whole group, freshness, policy, full-itinerary compatibility, economics, evidence/confidence. "No separar pasajeros automáticamente." "Una diferencia tarifaria de cero no implica ausencia de penalización." O1 LA2412 next day 08:15, fare diff 0, 4 seats, high confidence → candidate pending full validation; O2 LA2450 same day 23:40, 180000 CLP, 1 seat, medium → not eligible for whole group; O3 REFUND, low → needs further review. Do not assume Lima alternatives viable without validating arrival at Lima.
- **S13 D07 Automation.** Query, evaluate, inform, recommend only. No rebooking, compensation, refund, human-case creation, notification or booking changes. "No afirmar que se ejecutó una operación que solamente fue recomendada."
- **S14 D08 Independent states.** FlightStatus SCHEDULED/ON_TIME/DELAYED/CANCELLED/UNKNOWN; AssessmentStatus COMPLETE/PARTIAL/INDETERMINATE; RecommendationType NO_ACTION_REQUIRED/MONITOR_FLIGHT/REVIEW_REBOOKING_OPTIONS/HUMAN_REVIEW. Flight, connection, assessment, policy and recommendation states stay independent.
- **S15 D09 Privacy.** Allowlists + explicit mappers. Never expose passenger names, IDs, emails, phones, exact ages, full provider payloads. Minor presence may be used internally; public DTO exposes no unnecessary personal attributes. [A05] `decisionTrace` is internal only; public DTO may include verified facts, sanitized reason codes, policy refs, uncertainty warnings and metadata, not detailed contradictions, payloads, reconciliation hierarchy or personal attributes; `GROUP_INCLUDES_MINOR` is internal, public uses `PRIORITY_REVIEW_REQUIRED`. Internal `decisionTrace` keeps sanitized refs (events, policies, versions, timestamps, reasons). Logs: no PII or credentials.
- **S16 D10 Degradation.** Missing booking 404; invalid request 400; booking provider down 503/504; events provider down → INDETERMINATE when a safe response is possible; policies down → PARTIAL, no benefits guaranteed; alternatives down → PARTIAL, no unverified alternatives; invalid upstream → reject affected info and degrade when safe; unexpected → sanitized 500. "La ausencia de información no equivale a ausencia de disrupción." Valid PARTIAL may be HTTP 200. [A06] `INVALID_UPSTREAM_RESPONSE` → 502 when it prevents a safe assessment; otherwise controlled degradation (200, PARTIAL/INDETERMINATE).
- **S17 Providers.** Read: `get_trip_context(booking_id)`, `get_operational_events(segment_ids)`, `get_eligible_options(trip_context)`, `get_policy_rules(scenario)`. Write (future design only): `create_rebooking_request(option, idempotency_key)`, `create_human_case(reason, evidence)`, `notify_passenger(message)`. Interchangeable mock adapters for reads; synthetic fixtures; "No inventar endpoints externos ni conectar sistemas reales de aerolíneas."
- **S18 REST contract.** `POST /api/v1/disruptions/assessment`, request `{ "bookingId": "ABC123" }`; response has requestId, assessmentStatus, disruption, connection, policies, recommendation, alternatives, actions, metadata, sanitized decision refs. ABC123 → HUMAN_REVIEW, priority HIGH; public reason codes CONNECTION_AT_RISK, PRIORITY_REVIEW_REQUIRED (internal: GROUP_INCLUDES_MINOR), INCOMPLETE_FARE_CONDITIONS [A05]. [A04] priority ∈ LOW/NORMAL/HIGH, an attention recommendation, not a queue assignment. [A07] severity ∈ NONE/INFO/WARNING/CRITICAL/UNKNOWN (D01 mapping); ABC123: CRITICAL, PARTIAL, AT_RISK, HUMAN_REVIEW, HIGH. Zod at boundaries; errors inspired by RFC 9457; codes INVALID_REQUEST, BOOKING_NOT_FOUND, RATE_LIMIT_EXCEEDED, INVALID_UPSTREAM_RESPONSE, UPSTREAM_UNAVAILABLE, UPSTREAM_TIMEOUT, INTERNAL_ERROR. "El contrato exacto deberá documentarse y aprobarse antes de implementar el endpoint." Proposal: `docs/engineering/API-CONTRACT.md`.
- **S19 HTTP client.** Central Axios RestClient only when a concrete responsibility exists (timeout, correlation ID, interceptors, error normalization, latency, sanitization, bounded retries for safe reads only). "No realizar llamadas HTTP ficticias para justificar el uso de Axios." No circuit breakers/queues.
- **S20 Observability.** Pino structured logs (request ID, durations, provider latency/errors, outcome, contradictions, stale info, partial assessments, human-review recommendations); no PII; no public internal metrics; no mandatory Sentry. Product metrics are future work and must not be claimed as measured.
- **S21 AI.** "No utilizar LLM ni agentes en runtime de V1." Document (not implement) a hybrid evolution: AI interprets/explains, deterministic engine is authority, read-tool allowlist, structured validated outputs, deterministic fallback, human approval for impactful ops, no LLM write access.
- **S22 Security.** Synthetic fixtures only; no original PDF or process emails; no credentials/PII; no real env files; rate limiting; request size limit; sanitized errors; no stack traces; no full request body logging; read-only; document demo limitations. Review ODD/Engram/skills artifacts before publishing; no raw prompts, personal paths, auth config. Auth on real bookings is future work; "No simular mecanismos de seguridad inexistentes."
- **S23 Testing.** Test-first when applicable. Priority: ABC123; source reconciliation; degraded sources; stale events; delay boundaries 179/180/239/240; international condition; at-risk vs confirmed missed; group with minor; insufficient seats; stale alternatives; incomplete fare conditions; provider failures; no PII in public DTO; REST contract via Fastify inject. Parameterized tests where clearer; no arbitrary coverage; no full E2E if time-constrained. Scenarios: ABC123 HUMAN_REVIEW; DEMO01 normal → NO_ACTION_REQUIRED; DEMO02 190-min delay, no-fee change; DEMO03 unresolved contradiction → INDETERMINATE; DEMO04 stale events → INDETERMINATE; DEMO05 international 250-min delay, no-fee change + voucher; DEMO06 confirmed missed connection, no-fee change. Prioritize ABC123 and critical scenarios. [A08] Public: ABC123, DEMO01, DEMO02; DEMO03–DEMO06 are test fixtures only.
- **S24 Frontend.** Complementary; consumes real API; shows bookingId query, assessment status, itinerary, verified disruption, connection risk, recommendation, alternatives (verified/pending), loading/error/empty states, visible demo-mode label. Responsive, accessible. No business rules in React; no LATAM branding; no auth/admin/chatbot. May be cut to protect the primary track.
